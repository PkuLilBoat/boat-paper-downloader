# 下载流程与验收

本文描述公开版当前的执行边界，不包含逐站点经验配方或历史成功案例。

## 下载与回退

从 Skill 根目录运行 `scripts/scihub_downloader.py`。单个 DOI 先并行尝试开放获取和出版商 HTTP 路径，各自写入独立候选文件；首个通过基础 PDF 检查的候选被原子发布。同一轮同时完成时优先选择开放获取，并收集已完成任务的结果。

HTTP 未成功时，只使用已经配置且可用的代理，再进入有并发上限的浏览器阶段；源码保留最终 Sci-Hub 回退。访问依赖使用者自己的权限与环境，不保证任何特定网站成功。遇到认证、验证码或访问拒绝时报告实际阻塞，不改变系统网络设置或绕过访问控制。

`--worker-mode` 只执行 HTTP 阶段并生成原子结果清单；需要浏览器的条目交还协调者。`--fallback-only` 跳过 HTTP 阶段。PDF 到 Markdown 默认由协调者执行；`--no-convert` 用于仅保存 PDF。正式入库需要显式 `--organize-after-download` 和目标文献库规则。

## 本次任务的排障证据

结果中的 `strategy_attempts` 收集实际尝试及其结果，帮助区分候选、失败与浏览器落地页。`candidate` 仅表示取得通过基础字节检查的 PDF，不代表论文身份已核实。`reported_landing` 是落地页记录，不能作为已获取全文的证据。

以本次响应和页面为依据选择下一条受支持路径。重复失败时先判断是链接不存在、权限不足、页面挑战、预览器包装还是转换失败。记录阻塞并返回待处理条目，避免无变化重试。

这些记录只服务于本次任务。公开版不读取跨任务站点经验、不自动提升或排序历史路线，也不生成逐站点经验手册。`config/site_strategies.json` 只保存内置处理器的静态执行映射。内置处理器仍在公开源码中，不构成加密保护。

## 文件验收

1. 检查实际路径、PDF 可打开性和可读页；基础文件签名与大小检查只能确认候选。
2. 对照请求核对标题、作者、DOI 和版本。参考文献中出现目标 DOI 不能证明文件身份；补充材料、预览、勘误与正文必须区分。
3. 查看正文及结尾是否完整，版本是否符合任务。不能仅凭页数或下载状态宣称全文完整；无法确认时标记待核对，暂缓正式入库。
4. 单独检查 Markdown、图片及与 PDF 的内容对应情况。缺少 MinerU 或模型、转换失败、内容缺失均单独报告，不能倒推成 PDF 下载失败或成功转换。
5. 按 DOI 返回获取结果、来源/方法、实际路径、身份与完整性核对结论、转换结果和后续动作。共享回执前移除认证参数、Cookie 和凭据。

已有文件的存在不代表已通过上述审阅；更换候选前保留原文件。测试使用模拟网络和临时文件，不代表真实网站、账户权限或本地模型已经验收。

## 公开版边界

公开版保留通用获取、内置处理器、浏览器辅助、并发协调、转换和可选整理工具。本地完整版的站点记忆机制、学习排序、逐站点经验手册及历史验收台账不在当前发布文件树中。

早期公开提交中的文档仍可能通过 Git 历史访问。本次只更新当前文件树，不重写远程历史，不加入付费激活，也不改动本机完整版。
